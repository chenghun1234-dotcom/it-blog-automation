# UI 개선, 이거 그냥 색깔 몇 개 바꾸면 되는 거 아니었어? (feat. 폭풍 후회와 깨달음)

안녕하세요, 10년 차 개발자이자 테크 블로거, 오늘의 삽질(?) 경험을 공유할 푸닛입니다. 요즘 저는 신규 크리에이터들과 단순하고도 유기적인 커뮤니티를 만들고 싶은 분들을 위한 소셜 미디어 플랫폼, `Crowdwide` 개발에 매진하고 있습니다. 사용자 관심사에 맞춰 게시물과 콘텐츠를 보여주는 정교한 알고리즘을 갖추고 있어, 큰 커뮤니티 속에서도 새로운 사람들이 빠르게 성장할 기회를 잡을 수 있도록 돕는 게 목표죠.

현재 `Crowdwide`는 꽤 흥미로운 단계에 접어들었습니다. 핵심 기능들은 얼추 다 개발해 두었으니, 이제는 사용자 인터페이스(UI)를 다듬고 더 명확하고 깔끔하며, 우리 플랫폼만의 정체성을 담는 작업만 남았다고 생각했습니다.

솔직히, 이때까지만 해도 '에이, 이거 뭐 별거 있겠어? 색깔 좀 바꾸고 CSS 속성 몇 개만 더 입혀주면 끝나는 거 아니야?' 하는 안일한 마음이었습니다.

**하지만 제가 틀렸습니다. 그것도 아주 크게 말이죠... 😭**

`Crowdwide`의 UI를 꼼꼼히 뜯어보기 시작하면서 저는 경악했습니다. 어떤 곳은 `margin`이 절실했고, 또 다른 곳은 `padding`이 필요했습니다. 특히 프로필 페이지에서는 `border-radius` 하나가 페이지 전체의 인상을 망치고 있는 것을 발견했죠. 사소해 보이는 CSS 속성 하나하나가 사용자 경험에 얼마나 큰 영향을 미치는지 다시금 깨닫는 순간이었습니다. 이 모든 문제점을 하나씩 기록해나가니, 생각보다 훨씬 더 많은 부분을 손봐야 한다는 사실을 알게 됐습니다.

그러던 와중에 @effessdev 님이 'Optimistic UI'를 적용해보는 게 어떻겠냐는 기가 막힌 제안을 주셨습니다. 사실 그동안 저는 이 부분을 크게 중요하게 생각하지 않았습니다. 서버 응답이 빠르면 1~2초 안에 업데이트되는데, 굳이 사용자에게 즉각적인 피드백을 줄 필요가 있을까 싶었거든요. `Crowdwide`에 이 기능을 적용할 생각은 해본 적도 없었고, 이렇게 제안을 받을 줄은 상상도 못 했습니다.

하지만 **제가 실무에서 이 부분을 테스트해 봤을 때, 사용자 경험에 미치는 영향이 생각보다 크다는 걸 몸소 느꼈습니다.** 특히 네트워크 환경이 좋지 않거나, 사용자가 빠르게 여러 액션을 취할 때 1~2초의 대기 시간조차 지루하게 느껴질 수 있다는 점을 간과했죠. `effessdev`님 덕분에 이 중요한 부분을 놓치지 않고 개선할 수 있었습니다. 덕분에 이제는 이 기능도 깔끔하게 적용 완료했습니다! 정말 감사합니다!

UI와 레이아웃 개선에 대한 고민이 깊어질 때, Odinaka Robert Nnamani님, Rosana님, 그리고 Oleksandr님께서 정말 많은 도움과 훌륭한 제안들을 아낌없이 주셨습니다. 역시 옆집 동료 개발자들의 날카로운 시선은 다르더군요!

이분들의 조언을 바탕으로 사이드바를 대대적으로 개선했습니다. 이제 사이드바는 피드 레이어와 완전히 분리되어 독립적으로 열리고 닫힙니다. 사이드바가 열릴 때는 배경이 부드럽게 블러 처리되고 어두워지면서, 사용자 시선이 사이드바 내용에만 집중될 수 있도록 UX를 최적화했습니다. 또한, 기존의 그라디언트 배경이 너무 복잡하다는 판단하에 대부분 제거했습니다. 특정 공간에만 남겨두었는데, 훨씬 깔끔하고 세련된 느낌이 들어 만족스럽습니다.

자, 그래서 UI가 어떻게 바뀌었냐고요? 이제 `Crowdwide`의 새로운 모습들을 공개합니다!
