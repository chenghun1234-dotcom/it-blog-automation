# 당신의 깃허브 프로필은 벽지일 뿐? 저는 데이터로 숨 쉬는 우주 정거장을 만들었습니다.

불편하지만 부정할 수 없는 진실이 하나 있습니다. 깃허브 프로필 README는 당신이 작성할 파일 중 가장 많이 조회되지만, 사실 아무도 **제대로 읽지 않습니다.** 프로필에 접속했을 때 가장 먼저 눈에 들어오는 화면인데도 말이죠. 대부분 뱃지 몇 개, 커밋 스트릭 카운터, 그리고 '가장 많이 사용한 언어' 카드 정도로 채워져 있죠. 다른 사람들과 똑같은, 그저 밋밋한 '배경화면'처럼 스크롤만 쓱 내리게 만드는 평범한 모습입니다.

어느 날 저녁, 문득 이런 현실에 질려버렸습니다. '내 프로필은 그냥 바쁜 척하는 게 아니라, 뭔가 **제대로 작동해야 한다!**'라는 생각이 들었죠. 그렇게 2주가 흘렀고, 제 깃허브 프로필은 살아있는 행성을 공전하는 '미션 콘솔'로 변모했습니다. 화면에 보이는 모든 패널은 제 실제 데이터를 실시간으로 보여주는 정교한 계기판 역할을 하죠. 게다가 제가 잠든 사이, 매일 아침 스스로 업데이트됩니다.

이번 글에서는 이 모든 것을 해체해 보여드리겠습니다. 개발을 꽤나 힘들게 만든 독특한 제약사항부터, 이를 극복한 SVG 트릭, 행성 고리의 수학적인 원리, 그리고 제 주말을 송두리째 앗아간 세 가지 버그까지요. 이 모든 아이디어와 코드를 마음껏 가져가서 당신만의 '우주선'을 만들어보세요.

![Deep Field Survey — the hero console: a planet wrapped in contribution rings, with a live readout](https://raw.githubusercontent.com/rudratoshs/rudratoshs/main/shots/hero.png)
*메인 콘솔입니다. 고리는 제 커밋 기여도를, 판독값은 실시간 데이터를 보여줍니다.*

## 코드를 한 줄도 쓰기 전에 세운 단 하나의 규칙

포스트잇에 딱 한 문장을 적었습니다.

> **움직이는 모든 것은 의미를 지녀야 한다.**

이 단순한 규칙이야말로 단순한 '장난감'과 진정한 '대시보드'를 가르는 결정적인 차이였습니다. 정말 혹독했죠. 이 규칙 하나로 제 아이디어의 절반이 그 자리에서 폐기처분되었습니다. 그저 분위기만 내는 흐릿한 빛줄기? 예쁜 모양의 사인파 웨이브? 그런 건 전부 허용되지 않았습니다. 움직이는 픽셀 하나하나가 실제 숫자(커밋, PR, 언어 사용률, 블로그 글)와 연결되어 있어야만 했습니다. 그렇지 않으면 배포하지 않았어요.

이 생각을 잠시 붙들고 계세요. 나중에 제가 이 규칙을 어기고 다시 고쳐야 했거든요.

## 아무도 경고하지 않는 문제에 봉착하다

프로필을 애니메이션으로 꾸며보겠다고 의욕적으로 앉았는데, 시작부터 벽에 부딪혔습니다.

**깃허브 README는 자바스크립트를 실행할 수 없습니다.** `<script>`, `<canvas>`, WebGL, 클릭 핸들러 등 그 어떤 것도 허용되지 않죠. 깃허브는 보안상의 이유로 이 모든 것을 제거해 버립니다. 당신에게 허락된 건 마크다운과 이미지뿐입니다. 이게 바로 깃허브가 제공하는 모든 샌드박스 환경이죠.

그렇다면 제 프로필의 모든 요소는 어떻게 움직이고 있는 걸까요?

여기에 이번 글에서 가장 유용한 트릭이 숨어 있습니다. 바로 **SVG는 단순한 `<img>` 태그 안에서도 스스로 애니메이션을 실행할 수 있다는 점입니다.** 깃허브는 스크립트를 제거하지만, SVG 내부에 선언적으로 포함된 애니메이션, 즉 순수한 CSS `@keyframes`와 SMIL은 그대로 둡니다. 다음 코드를 README에 넣어보세요.

```xml
<svg xmlns="http://www.w3.org/2000/svg" width="200" height="60">
  <style>
    .dot { animation: pulse 1.8s ease-in-out infinite; }
    @keyframes pulse { 50% { opacity: .2; } }
  </style>
  <circle class="dot" cx="30" cy="30" r="8" fill="#5bd6ff"/>
</svg>
```

...그리고 `![](badge.svg)`처럼 이미지로 참조하면, 저 점은 영원히 숨 쉬듯이 깜빡입니다. 깃허브가 코드를 실행할 수 없다고 단언했던 파일 안에서 말이죠. 제가 실무에서 이 부분을 테스트해 봤을 때, 이런 선언적 애니메이션이 꽤 광범위하게 허용된다는 사실에 적잖이 놀랐습니다. 이 단 하나의 허점이 지금부터 보여드릴 모든 것의 기반입니다. 행성을 둘러싼 회전하는 고리, 레이더 스윕, 깜빡이는 판독값 모두 이미지를 가장한 SVG일 뿐입니다.

이제 콘솔을 만들어 봅시다.

## 행성은 내 기여 그래프를 고리로 두르고 있다

메인 화면의 핵심은 느리게 자전하는 행성입니다. 그리고 이 행성을 둘러싼 고리들은 단순한 장식이 아닙니다. 제 깃허브 기여 달력을 궤도 형태로 구부려 놓은 것이죠.

일주일을 나타내는 7개의 고리가 있고, 각 고리는 한 해의 주(week)를 나타내는 53개의 조각으로 나뉩니다. 각 조각은 제가 해당 요일에 얼마나 열심히 커밋했는지에 따라 시안색, 민트색, 황금색으로 빛납니다. 커밋이 적었던 달은 얇고 어두운 안쪽 고리로 나타나고, 스프린트 기간에는 밝은 띠가 적도를 따라 빛납니다.

이 모든 것을 저렴하게 구현하게 해준 비결은 SVG의 한 줄짜리 슈퍼파워인 `pathLength`입니다. 각 고리에 "너의 둘레는 53단위 길이야"라고 알려주면, 이제 **1단위 = 1주**가 되어 대시 패턴으로 주별 활동을 그릴 수 있게 됩니다.

```js
// 각 고리는 요일별로 구성되며, 53개 세그먼트는 1년 53주를 나타냅니다.
<ellipse pathLength="53"
         stroke-dasharray="0 12  0.7 0.3  0 40"  /* 공백, 대시(주), 공백... */
         ... />
```

느린 드리프트 애니메이션은 전체 시스템이 살아 움직이는 듯한 느낌을 줍니다.

```css
.ring { animation: ringdrift 90s linear infinite; }
@keyframes ringdrift { to { stroke-dashoffset: -53; } }
```

마지막으로 3D 효과를 주기 위한 한 가지 터치가 있습니다. 고리들을 앞쪽 절반과 뒤쪽 절반으로 나누어 행성의 양쪽에 그리는 것입니다. 이렇게 하면 고리가 위쪽에서는 행성 뒤로, 아래쪽에서는 행성 앞으로 지나가는 것처럼 보입니다. 이 트릭이 없었다면 그냥 스티커처럼 보였을 겁니다. 하지만 이 효과 덕분에 행성이 자신의 궤도 안에 제대로 앉아 있는 것처럼 느껴집니다.

## 레이더, 스펙트럼, 그리고 잘못 만들었던 시그널 패널

세 가지 계기판이 더 있고, 이들 역시 포스트잇에 적었던 그 규칙을 충실히 지킵니다.

**레이더**는 제 오픈소스 활동의 발자취를 보여줍니다. 제 레포가 아닌 **다른 사람들의 레포**에 올린 풀 리퀘스트, 즉 내 레포 목록에는 절대 나타나지 않는 작업들이죠. 각 블립(Blip)은 실제 PR을 나타냅니다. 접시가 스윕하고, 지나갈 때마다 블립이 '핑' 소리를 내며 반응합니다.

![Radar panel — external pull requests as blips on a sweeping scope](https://raw.githubusercontent.com/rudratoshs/rudratoshs/main/shots/ops.png)

**스펙트럼**은 제가 사용하는 언어들을 별빛 스펙트럼처럼 방출선으로 보여줍니다. 굵은 시안색 선은 타입스크립트, 얇은 초록색 줄무늬는 셸 스크립트를 의미하죠. 이 선들의 너비는 단순히 시각적인 효과가 아니라, 실제 언어 사용 비율을 반영합니다.

![Spectrum panel — languages rendered as emission lines](https://raw.githubusercontent.com/rudratoshs/rudratoshs/main/shots/spectrum.png)

**시그널**은 제가 가장 자랑스러워하는 부분입니다. 왜냐하면 처음엔 완전히 잘못 만들었었거든요. 약 10분 동안 아름다운 사인파 형태의 파형을 보여주었지만... 그건 아무 의미도 없었습니다. 규칙을 어긴 것이었죠. 그래서 저는 과감히 뜯어내고, 처음부터 보여줬어야 할 데이터를 그렸습니다. 바로 **dev.to의 게시물별 반응 수**입니다.

이제 오실로스코프의 가장 높은 스파이크는 제가 가장 많은 반응을 얻은 아티클을 의미합니다. 스윕은 각 게시물을 차례로 '가로지르며' 정보를 표시하죠. 마치 전송 로그처럼 읽히며, 100% 제 실제 참여도를 나타냅니다. 가짜 파형을 실제 숫자로 바꾸는 순간, 이 패널은 단순한 스크린세이버에서 유용한 대시보드로 탈바꿈했습니다. 이것이 바로 하나의 커밋 속에 담긴 이 프로젝트의 핵심 철학입니다.

![Signal panel — reactions per post plotted as an oscilloscope](https://raw.githubusercontent.com/rudratoshs/rudratoshs/main/shots/transmissions.png)
*시그널 패널: 각 점은 게시물이며, 스파이크는 가장 많은 반응을 얻은 게시물입니다.*

## 열 개의 파일이 하나의 화면으로 보이다

프로필은 마치 하나의 통합된 콘솔처럼 보이지만, 실제로는 README에 쌓여있는 **열 개의 독립적인 SVG** 파일들입니다. 영웅 패널, 링크 뱃지, 미션, 레이더, 스펙트럼, 시그널, 푸터 등이죠.

```md
![hero](./svg/hero.svg)
![missions](./svg/missions.svg)
![radar](./svg/ops.svg)
![spectrum](./svg/spectrum.svg)
![signal](./svg/transmissions.svg)
```

왜 굳이 이렇게 나누었을까요? 하나의 거대한 SVG는 유지보수하기가 정말 고통스럽고, 각 패널의 높이도 제각각이기 때문입니다. 문제는 이미지를 쌓아 올리면 아주 미세한 선들이 생겨서 통합된 착시 효과가 깨진다는 점이었습니다. 해결책은 '공유 크롬(shared chrome)'을 사용하는 것이었습니다. 모든 패널이 동일한 모서리 브래킷, 동일한 베젤, 그리고 동일한 스캔 라인을 그리도록 만들었죠. 그래서 열 개의 이미지가 마치 하나의 연속된 화면처럼 보이게 됩니다.

```css
.scan { animation: scan 8s linear infinite; }
@keyframes scan { from { transform: translateY(-90px); } to { transform: translateY(100%); } }
```

일관성이라는 트릭이 여러 장의 그림을 하나의 정교한 기계로 바꿔놓는 열쇠였습니다.

![Missions panel — flagship repos as mission dossiers](https://raw.githubusercontent.com/rudratoshs/rudratoshs/main/shots/missions.png)
*열 개의 패널 중 하나입니다. 주요 레포들을 미션 파일처럼 보여주며, 각 레포는 자체 공전하는 달을 가지고 있습니다.*

## 매일 아침 스스로 보고서를 제출하다

이 부분은 저에게 여전히 마법처럼 느껴집니다. 저는 이 프로필에 전혀 손대지 않습니다.

예약된 깃허브 액션이 매일 작은 Node 스크립트를 실행하여 최신 데이터를 가져오고, 열 개의 SVG를 모두 다시 생성한 다음, 변경된 내용이 있으면 커밋합니다.

```yaml
on:
  schedule: [{ cron: '17 3 * * *' }]   # 03:17, 03:00이 아닌 이유가 있습니다. 아래를 보세요.
  workflow_dispatch:
```

(왜 정각인 03:00이 아니라 03:17에 실행되냐고요? 지구상의 거의 모든 크론 잡이 정각에 실행되면서 깃허브의 스케줄러가 마비되는 경우가 많기 때문입니다. 17분은 비교적 한가한 시간대라 제 시간에 제대로 실행되죠. 이 사실을 아주 귀찮은 방식으로 배웠습니다.)

데이터는 두 곳에서 가져옵니다. 깃허브 GraphQL API는 전체 기여 달력 데이터를 단 **한 번의 호출**로 제공하며, 저는 이 강도 레벨을 고리 색상에 바로 매핑합니다.

```js
const LEVEL = { NONE:0, FIRST_QUARTILE:1, SECOND_QUARTILE:2, THIRD_QUARTILE:3, FOURTH_QUARTILE:4 };
weeks[w][day] = LEVEL[contributionLevel];   // → 어떤 고리 세그먼트가 얼마나 밝게 빛날지
```

블로그 글 시그널은 dev.to의 공개 API에서 가져옵니다. 별도의 API 키가 필요 없어서 액션에 추가적인 시크릿을 설정할 필요가 없습니다.

```js
const posts  = await (await fetch(`https://dev.to/api/articles?username=${me}&per_page=30`)).json();
const signal = posts.slice(0, 16).map(p => p.public_reactions_count).reverse();  // 오실로스코프 데이터
```

이 시스템이 지루할 정도로 안정적으로 작동하게 하는 세 가지 습관이 있습니다. 첫째, **소프트하게 실패합니다.** (API 문제가 발생하면 어제 데이터가 그대로 유지되고 빈 콘솔이 배포되지 않습니다.) 둘째, **실제 변경 사항이 있을 때만 커밋합니다.** (불필요한 히스토리를 만들지 않죠.) 셋째, 토큰은 레포에 직접 저장되지 않고 깃허브 액션 시크릿에 보관된 **세분화된 읽기 전용 PAT**를 사용합니다.

## 제 주말을 앗아간 세 가지 버그

모든 프로젝트에는 당신에게 무언가를 가르쳐주는 버그들이 있습니다. 가장 심각했던 것부터 가장 어리석었던 것까지, 제 프로젝트에서 발생했던 버그들입니다.

**1. 7MB짜리 행성이 회전하지 않았다.** 72프레임으로 회전하는 지구본을 영웅 SVG에 넣으려고 한 시간 동안 신나게 삽질했습니다. 그러다 깃허브가 SVG를 이미지로 렌더링할 때, **중첩된 애니메이션은 첫 프레임에서 멈춘다**는 사실을 알게 되었죠. 게다가 파일 크기는 7MB로 불어나 있었습니다. 교훈: 선언적인 SVG 애니메이션은 이미지 샌드박스에서 살아남지만, 그 안에 쑤셔 넣은 비디오는 그렇지 않다는 겁니다. 그래서 지구본은 선명한 정지 이미지로 두고, **고리**가 회전하게 만들었습니다. (실제로 회전하는 행성은 독립적인 웹 버전에서 볼 수 있는데, 그곳에서는 진정한 움직임이 허용되죠.)

**2. 사라진 막대 그래프.** 통계 막대가 한 줄 통째로 렌더링되지 않았습니다. 에러도 없었죠. 그저 텅 빈 트랙만 있었습니다. 원인은? 각 막대가 `<span>` 태그였고, **인라인 요소는 `width`와 `height` 속성을 무시합니다.** `display:block` 하나를 추가하자마자 모든 막대가 제자리를 찾았습니다. 10년 차 개발자인 저도 여전히 CSS가 이렇게 허를 찌를 때면 '아, 다시 초심으로 돌아가야겠구나' 하는 생각이 들곤 합니다.

**3. 거짓말하는 폰트.** 제 컴퓨터에서는 모든 것이 완벽하게 보였지만, 다른 사람들의 화면에서는 미묘하게 틀어졌습니다. 제목이 한 글자 일찍 줄바꿈되거나, 자간이 어긋나거나. 시스템 폰트 폴백이 조용히 일어났던 거죠. 해결책은 제가 실제로 사용하는 약 80개의 글리프만으로 폰트를 서브셋하고, 이를 base64로 인코딩하여 포함시키는 것이었습니다. 덕분에 어디서든 텍스트가 픽셀 단위로 동일하게 보이고, 파일 크기도 여전히 작게 유지할 수 있었습니다.

## 그래서... 그만한 가치가 있었을까요?

솔직한 피해 보고서: 수작업으로 만든 10개의 SVG 생성기, 고리 투영 시스템, 폰트 서브셋 단계, 두 가지 소스의 데이터 파이프라인, 그리고 매일 작동하는 로봇. 이 모든 것을 겨우 4초 만에 훑어보는 파일 하나를 위해 만들었습니다.

네, 그만한 가치가 있었습니다. 이유는 이렇습니다. 그저 '멋있어 보이는' 프로필은 일회성으로 끝납니다. 스크린샷 찍고 다음으로 넘어가죠. 하지만 고리가 내 달력이고, 레이더가 내 오픈소스 활동 흔적이며, 시그널이 내 독자층을 보여주는 프로필은 훨씬 더 교묘한 의미를 지닙니다. 바로 **'커리어를 위한 상태 대시보드'**인 셈이죠. 무언가를 만들어낼 때는 조용히 나에게 보상을 주고, 그렇지 않을 때는 솔직하게 현실을 보여줍니다. 이 '책임감'이야말로 진정한 기능이었고, 덕분에 저는 다시금 제 프로필에 관심을 갖게 되었습니다. 이 모든 SF적인 요소 뒤에 숨겨진 작지만 진실된 가치였죠. 개인적으로 이 프로젝트를 통해 제 데이터가 시각적으로 살아 숨 쉬는 걸 보면서, 저 스스로에게 더 솔직해지고 동기 부여를 받는 신기한 경험을 했습니다.
