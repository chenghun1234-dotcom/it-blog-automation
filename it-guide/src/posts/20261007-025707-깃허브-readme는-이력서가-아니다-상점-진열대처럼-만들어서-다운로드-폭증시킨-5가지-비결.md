## 흔한 '멋진' 프로필들의 문제점

인기 있는 깃허브 프로필 README 10개를 열어보세요. 대부분 비슷한 것들을 발견할 겁니다.

*   배지들의 향연
*   커밋 수를 보여주는 통계 카드
*   "안녕하세요 👋 저는 ___ 입니다" 같은 자기소개 한 줄
*   컨트리뷰션 그래프를 먹고 있는 뱀 애니메이션

이 모든 것들은 그저 '장식'에 불과합니다. 방문자가 처음 3초 안에 던지는 가장 중요한 질문, 즉 "이 사람에게서 지금 당장 무엇을 얻을 수 있지?"라는 질문에 그 어느 것도 답해주지 못하죠.

### *"이 개발자가 나에게 지금 바로 줄 수 있는 가치는 무엇일까?"*

저는 ATLOCK, APIC, ANOTE, ACALCU 같은 데스크톱 앱을 개발합니다. 그래서 스스로에게 다른 질문을 던져봤습니다.

**만약 제 README가 앱 스토어 목록처럼 작동한다면 어떨까?**

## '상점 진열대' README를 위한 5가지 규칙

### 규칙 1: 3초 다운로드 테스트

방문자가 랜딩 후 3초 이내에 여러분의 가장 좋은 결과물을 다운로드할 수 없다면, 그 페이지는 실패한 겁니다.

그래서 저는 각 앱마다 고유한 카드를 만들었고, **모든 카드 바로 아래에 실제 `.zip` 릴리스로 연결되는 다운로드 버튼**을 배치했습니다. "릴리스 보기" 같은 중간 단계나 헤매는 과정은 일절 없습니다. 제가 이 원칙을 적용하고 나서 가장 크게 체감한 건, 사람들이 제 페이지를 탐색하는 시간이 극적으로 줄었다는 점이었죠.

```html
<td align="center">
  <a href="https://github.com/USER/APP">
    <img src="assets/app_card.svg" width="408" alt="APP">
  </a><br>
  <a href="https://github.com/USER/APP/releases/download/TAG/APP.zip">
    <img src="https://img.shields.io/badge/⬇%20DOWNLOAD%20APP-B8935F?style=for-the-badge&labelColor=8a6c3f&logo=windows&logoColor=white" height="38">
  </a>
</td>
```

위에 앱 카드, 바로 아래에 액션 버튼. 앱 스토어 목록과 동일한 패턴이죠.

### 규칙 2: 하나의 메탈을 선택하고 고수하라

제 선택은 **골드**입니다. 밝은 톤은 `#B8935F`, 그림자 톤은 `#8a6c3f`를 사용했죠.

링-라이트 로고, 섹션 헤더, 버튼, 카드 가장자리까지 모든 요소에 이 색상을 적용했습니다. 모든 요소가 하나의 팔레트를 공유하기 때문에, 페이지는 단순히 조립된 것이 아니라 잘 디자인된 것처럼 보이게 됩니다.

*배지들이 싸구려처럼 보이는 이유는 모든 색상이 한꺼번에 사용되기 때문입니다.*

### 규칙 3: 모든 곳에 하나의 너비

제 프로필에 있는 모든 전체 너비 이미지는 **830px**입니다. 이게 제 레이아웃 시스템의 전부예요.

어떤 요소도 옆 요소보다 약간 넓거나 좁지 않습니다. 덕분에 페이지는 위젯 더미처럼 보이지 않고, 하나의 깔끔한 컬럼처럼 읽힙니다. 앱 카드는 408px인데, 이는 830px 안에 두 개의 카드와 그 사이의 여백이 딱 들어맞는 크기입니다. 프런트엔드 관점에서 보면, 이처럼 일관된 레이아웃은 사용자가 정보를 훨씬 편안하게 소화하도록 돕는 중요한 디자인 원칙이 됩니다. 이 게시물에서 단 하나의 규칙만 복사해야 한다면, 바로 이 규칙을 복사하세요.

### 규칙 4: 섹션 이름을 경로처럼 지어라

제 헤더는 "About Me"나 "Projects"가 아닙니다. 이렇게 되어 있죠.

```plaintext
~/links
~/apps
~/status
~/stack
```

별도의 비용이 드는 것도 아닌데, 개발자에게 페이지를 만든 사람이 터미널 환경에 익숙한 사람이라는 것을 반 초 만에 알려줍니다. 또한 모든 헤더가 동일하게 보이고 같은 위치에 있어 페이지를 빠르게 훑어보기에도 좋습니다.

### 규칙 5: 선언문은 단락이 아닌 디자인 요소로 만들어라

페이지 한가운데에 다음과 같은 배너를 넣었습니다.

> **제로 텔레메트리. 제로 클라우드. 제로 구독. 제로 광고.**

이것은 단순히 자기소개 문구가 아닙니다. 전체 제품 철학을 담은, 전체 너비의 이미지로 렌더링된 핵심 선언문이죠. 그리고 페이지는 한 문장으로 마무리됩니다.

> *당신의 기기. 당신의 데이터. 당신의 통제.*

방문자들은 불릿 리스트를 기억하지 못합니다. 그들은 반복할 수 있는 한 줄짜리 문구를 기억하죠.

## '위젯 없음' 결정

저는 한 가지 어려운 결정을 내렸습니다. **제 페이지의 모든 시각적 요소는 제 리포지토리 안에 있습니다.**

다른 서버에서 가져온 통계 카드도 없고, 무료 서비스가 중단되면 빈칸이 되어버리는 스트릭 카운터도 없습니다. 타사에서 URL을 변경하면 사라져 버릴 이미지도 없죠. 제가 예전에 외부 위젯에 의존했다가 서비스가 종료되거나 URL이 바뀌면서 프로필이 망가진 경험이 몇 번 있었거든요. 그 이후로는 무조건 제 레포 안에 모든 걸 두는 습관을 들였습니다.

제 카드, 헤더, 히어로 이미지, 푸터는 모두 `/assets` 폴더 안에 있는 SVG 파일이며, 외부에서 가져오는 유일한 요소는 다운로드 배지뿐입니다. (만약 이마저도 제거해야 한다면, 제 자체 SVG로 교체할 수 있습니다.)

중요한 두 가지 세부 사항:

*   **이미지에 `raw.githubusercontent.com` 절대 URL을 사용합니다.** 덕분에 README가 복사되거나 미러링되거나 다른 곳에서 미리보기 되어도 여전히 올바르게 렌더링됩니다.
*   **선언문 배너를 포함한 모든 요소에 `alt text`를 적용했습니다.** 스크린 리더 사용자나 이미지가 로드되지 않을 때도 페이지가 제대로 작동하도록 하기 위함이죠.

## 한눈에 보는 구조

```plaintext
[ 링-라이트 로고 ]
[ 히어로: whoami ]
[ ~/links  → 웹사이트 · 블로그 · 링크드인 · 피어리스트 · 인스타그램 ]
[ ~/apps   → 2x2 카드 그리드, 각 카드에는 DOWNLOAD 버튼 ]
[ ~/status → 제로 텔레메트리 배너 ]
[ ~/stack  → 기술 스택 ]
[ footer   → "당신의 기기. 당신의 데이터. 당신의 통제." ]
```

단 6개의 섹션과 앱당 하나의 액션. 페이지에 단순히 공간을 채우기 위한 요소는 아무것도 없습니다.
