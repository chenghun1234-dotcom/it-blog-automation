# 아니, 이게 된다고? {} + [] = 0이 합리적인 자바스크립트의 비밀 (ft. 타입 강제 변환)

자바스크립트(JavaScript). 이 전설적인 프로그래밍 언어는 1990년대 중반, 넷스케이프가 마이크로소프트를 견제하기 위해 고작 10일 만에 뚝딱 만들어졌죠. 당시 브라우저 전쟁의 한복판에서 태어났지만, 계획대로 되지 않았다는 건 우리 모두가 아는 사실이고요. 오늘날 어떤 개발자들은 자바스크립트를 극찬하고, 어떤 이들은 저주하며, 또 어떤 이들은 그저 놀림거리로 삼습니다. 하지만 부정할 수 없는 진실은 단 하나입니다. **이 언어가 없었다면, 현대 웹은 지금처럼 존재할 수 없었을 겁니다!**

수십 년에 걸쳐 자바스크립트는 셀 수 없는 혁명을 거듭했습니다. 요즘 자바스크립트의 역량은 1990년대의 그것과는 비교조차 할 수 없을 정도로 비약적인 발전을 이뤘죠. 하지만 여기엔 아주 작은, 아니 어쩌면 엄청나게 큰 문제가 하나 있습니다. 언어에 어떤 변화를 주든, 수많은 기존 웹사이트들이 여전히 옛 자바스크립트 동작 방식에 의존하고 있다는 사실을 반드시 고려해야 한다는 점입니다. 그리고 그 중 일부 웹사이트들은 아마 영원히 그 코드를 그대로 실행할 테고요.

그래서 말인데, **자바스크립트의 이 기묘함은 아마도 영원히 우리 곁에 머무를 겁니다!** 😂

오랜만에 제 블로그에서 한때 인기가 많았던 **JS WTF** 시리즈를 다시 꺼내든 건 아주 단순한 이유 때문입니다. iJS 뮌헨에서 돌아오는 길인데, 프랑크푸르트 공항에서 비행기를 갈아타기까지 두 시간이 남아버렸지 뭡니까… (묻지 마세요). 심오하고 기술적인 글을 쓰기엔 턱없이 부족한 시간이지만, 그렇다고 벽만 멍하니 쳐다보기엔 너무나 긴 시간이죠.

자, 그럼 제가 가장 좋아하는 자바스크립트 구문 중 하나를 살펴봅시다:

```javascript
{} + [] // 0
```

네, 맞습니다. 잘못 본 게 아닙니다. 특정 조건에서 빈 객체에 빈 배열을 더하면 자바스크립트에서는 `0`이 나옵니다. **그리고 놀랍게도, 이건 완벽히 합리적입니다!** 🤡

## 잠깐, 뭐라고요? 왜 이런 일이 발생하죠?

가장 먼저 알아야 할 것은 자바스크립트가 이런 상황에서 **`{}`를 무조건 객체로 해석하지 않는다는 점입니다!** 문맥에 따라 자바스크립트 파서는 이 표현식을 완전히 다른 두 가지로 처리할 수 있습니다.

일반적인 자바스크립트 스크립트에서 문장의 시작에 오는 다음 코드를 보세요.

```javascript
{} + []
```

자바스크립트는 이것을 이렇게 해석할 수 있습니다:

```javascript
{}    // 빈 코드 블록 (empty block of code)
+[]   // 단항 덧셈(unary plus) 연산자가 빈 배열에 적용됨 (무슨 일이 생길까요?)
```

그렇습니다. 첫 번째 `{}`는 전혀 객체 리터럴이 아닙니다. 그냥 아무것도 하지 않는 빈 코드 블록일 뿐입니다. 그럼 두 번째 부분은요? 바로 여기서부터 재미가 시작됩니다. **제가 실무에서 이런 코드를 만나 디버깅할 때 가장 먼저 확인하는 부분이 바로 `{}`가 문맥상 객체인지, 블록인지 파악하는 겁니다. 이 사소한 차이가 예상치 못한 동작의 핵심 원인이 될 때가 많죠.**

## 타입 강제 변환의 마법 ✨

이 표현식:

```javascript
+[]
```

은 우리에게 사랑받는 언어가 자랑하는 기능 중 하나인 **타입 강제 변환(type coercion)**의 전형적인 예시입니다.

아마 다들 아시겠지만, 자바스크립트는 동적(dynamically typed)이면서 약한 타입(weakly typed) 언어입니다.

동적 타입이란 변수가 특정 타입에 영구적으로 묶여있지 않다는 것을 의미합니다. 변수에 숫자를 할당했다가 나중에 문자열로 바꿔도 자바스크립트는 아무런 불평을 하지 않습니다.

하지만 그것만이 아닙니다! 자바스크립트는 또한 암시적 타입 변환을 수행하며, 이것이 종종 "약한 타입"으로 불리는 이유 중 하나입니다. 그리고 때때로 이러한 변환은 다소… 창의적인 결과를 만들어냅니다.

우리의 단항 덧셈 연산자를 다시 봅시다:

```javascript
+[]
```

숫자를 더하거나 문자열을 연결하는 이항 `+` 연산자와 달리, **단항 `+` 연산자는 피연산자를 숫자 값으로 변환하려고 시도합니다.** 이 경우, 기본적으로 다음과 같이 동작합니다.

```javascript
Number([])
```

네, 배열을 숫자로 변환하려는 겁니다. 왜 안 되겠습니까?

하지만 자바스크립트가 이 작업을 완료하려면 또 다른 변환을 수행해야 합니다. 배열은 객체이므로 자바스크립트는 먼저 배열로부터 원시 값(primitive value)을 얻어야 합니다. 일반적인 빈 배열의 경우, 이 과정은 `toString()` 메서드를 호출하는 것으로 끝납니다.

그리고 예상하셨겠지만,

```javascript
[].toString(); // ""
```

빈 배열은 빈 문자열이 됩니다.

따라서 우리의 변환은 실질적으로 다음과 같이 됩니다:

```javascript
Number([]);

// 첫째, 배열은 원시 문자열이 됩니다:
Number("");

// 그리고 빈 문자열은:
0
```

왜냐하면:

```javascript
Number("") // 0
```

그러므로:

```javascript
+[] // 0
```

이는 우리의 원래 구문:

```javascript
{} + []
```

이 빈 코드 블록 뒤에 단항 덧셈 연산자로 파싱될 때, 실질적으로 다음과 같이 변환된다는 의미입니다:

```javascript
{} // 아무것도 하지 않는다

+[] // 0
```

**그리고 이렇게 해서 우리는 `0`을 얻게 됩니다!** 간단하고 명확하죠? 🤡

솔직히 말해서, 정확히 이 구문이 이렇게 완벽하게 정상적으로 보이는 결과를 만들어내는 다른 언어는 떠오르지 않습니다. 심지어 우리가 사랑하는 PHP조차도 이런 식으로는 치명적인 오류를 뱉어낼 겁니다. 물론 PHP도 자체적인 흥미로운 놀라움들을 잔뜩 가지고 있으니 너무 가혹하게 판단해서는 안 되겠죠.

한 가지 중요한 세부 사항: **이러한 동작은 코드가 어떻게 파싱되는지에 따라 달라집니다.** 예를 들어:

```javascript
// 일반적인 스크립트에서, 독립적인 문장으로:
{} + [] // 0

// 자바스크립트가 {}를 객체로 해석하도록 강제하려면:
({} + []) // "[object Object]"

// 함수 호출 내부에서는:
console.log({} + []); // "[object Object]"
```
이런 파싱의 미묘한 차이는 실제로 복잡한 라이브러리 코드를 분석하거나, 특정 환경에서 예상치 못한 동작을 만났을 때 디버깅의 핵심 단서가 되기도 합니다.

## 그럼 `[] + []`는요?

이제 타입 강제 변환을 이해하셨으니, 이 결과는 당연하게 느껴질 겁니다:

```javascript
[] + [] // ""
```

여기서는 이항 `+` 연산자를 다루고 있습니다. 자바스크립트는 두 배열을 모두 원시 값으로 변환합니다. 글쎄요, 두 개의 빈 문자열을 더할 때 무엇을 기대하겠습니까? 😀 아무것도 없는 것에 아무것도 없는 것을 더하면 아무것도 없습니다! 아름답네요.

## 그리고 이제 덧셈은 교환법칙조차 성립하지 않는답니다 😂

같은 논리로, 다른 표현식을 시도해봅시다:

```javascript
[] + {} // "[object Object]"
```

잠깐만요.

방금 우리가 이렇게 된다는 것을 확인하지 않았나요?

```javascript
{} + [] // 0
```

그런데 피연산자의 순서를 바꾸자마자 완전히 다른 결과가 나오는 건 왜일까요? 자바스크립트에서는 덧셈의 교환법칙조차 선택사항인 모양입니다. XD

음, 기술적으로 말하면 우리는 항상 수학적 덧셈을 수행하는 것이 아니며, 파서가 이러한 표현식을 다르게 처리하는 것이 맞습니다.

하지만 좋은 농담을 기술적인 세부 사항으로 망치지는 맙시다. 실제로 어떤 일이 벌어지는지 살펴보죠. 이 표현식에서:

```javascript
[] + {}
```

빈 배열은 빈 문자열이 됩니다:

```javascript
[].toString() // ""
```

그럼 빈 객체는요? 일반적인 자바스크립트 객체는 자체적으로 멋진 문자열 표현을 가지고 있습니다:

```javascript
({}).toString() // "[object Object]"
```

따라서 자바스크립트는 실질적으로 다음을 수행합니다:

```javascript
"" + "[object Object]"
```

그러면 다음과 같은 결과가 나옵니다:

```javascript
"[object Object]"
```

그리고 이게 전부입니다! **도리깨 만드는 것만큼 쉽죠?** 이 말은 폴란드 속담 *proste jak budowa cepa*를 직역한 것으로, 뭔가 터무니없이 이해하기 쉽다는 뜻입니다. 그리고 저는 이 말이 자바스크립트에 완벽하게 어울린다고 생각합니다. 😂
