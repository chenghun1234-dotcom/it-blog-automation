# DEV.to 덕후가 직접 만든! 새 탭을 'DEV Tab'으로 바꾸면 생기는 일

요즘 DEV에서 보내는 시간이 부쩍 많아졌습니다. 흥미로운 글을 읽고, 멋진 프로젝트를 발견하고, 챌린지에 참여하기도 하고, 가끔은 직접 글을 쓰기도 하죠.

동시에 [daily.dev](https://daily.dev/)도 즐겨 사용합니다. 새 탭을 열 때마다 개발자 콘텐츠 피드가 바로 눈앞에 펼쳐지는 게 정말 편리하거든요.

그러다 문득 이런 생각이 들었습니다. 'daily.dev처럼 새 탭에서 DEV 콘텐츠를 바로 볼 수 있다면 어떨까?' 하는 아이디어였죠.

그리고 저는 아이디어가 떠오르면 꼭 프로젝트로 만들어야 직성이 풀리는 개발자인지라, 결국 하나를 만들어냈습니다.

이름은 **DEV Tab**. DEV의 게시물 피드로 새 탭 페이지를 대체하는 무료 오픈소스 브라우저 확장 프로그램입니다.

이제 크롬 웹 스토어에서 바로 만나볼 수 있습니다.

**[크롬용 DEV Tab 설치하기](https://chromewebstore.google.com/detail/dev-tab/mfhbilfjgklgebkclbkabohhkibomnop)**

파이어폭스 지원도 이미 구현되어 있으며, 현재 애드온 승인을 기다리고 있습니다. 승인되는 대로 이 글에 링크를 업데이트하겠습니다.

## 단순히 피드만 보여주는 건 아닙니다

처음 아이디어는 아주 단순했어요. 새 탭을 열고, DEV에 무슨 일이 일어나고 있는지 보고, 관심 가는 게시물을 클릭해서 이동하는 거죠.

하지만 늘 그렇듯이, 자꾸만 추가하고 싶은 기능들이 머릿속을 맴돌았습니다.

![DEV 게시물 그리드를 보여주는 DEV Tab](https://raw.githubusercontent.com/pinkpixel-dev/DEV-tab/main/screenshots/screenshot.png)

'오늘', '이번 주', '인기 상승 중', '최신' 게시물을 둘러볼 수 있을 뿐만 아니라, 트렌드, 이벤트, 팟캐스트, 영상 전용 섹션도 마련되어 있습니다. 제가 실무에서 여러 커뮤니티를 돌아다니며 정보를 얻는데, 이런 분류와 태그 필터 기능이 실제 자료 탐색 시간을 확 줄여주더군요.

물론 태그 필터도 있습니다. 관심 있는 주제 사이를 빠르게 오갈 수 있죠. 좋아하는 태그를 저장하거나, 보고 싶지 않은 태그는 숨길 수도 있고, 특정 DEV 조직의 게시물만 팔로우하는 것도 가능합니다.

이 외에도 몇 가지 더 추가한 기능들이 있어요:

-   새 탭 페이지에서 바로 DEV 검색
-   화살표 키와 Enter를 사용한 키보드 탐색
-   더 많은 게시물과 적은 이미지를 선호한다면 '간결한 보기'
-   반응(Reaction) 수와 최신 댓글 3개 미리보기
-   새 DEV 게시물 작성을 위한 바로가기
-   피드 캐싱: 새 탭을 열 때마다 모든 내용을 다시 로드하느라 기다릴 필요가 없습니다.

딱히 혁명적인 기능은 없습니다. 그저 DEV를 편리하게 탐색하고 싶었고, 뭔가 찾으러 다니지 않아도 되게끔 만들고 싶었을 뿐이죠.

## 그러다 대시보드의 필요성을 느꼈습니다

이 부분은 원래 계획에 없던 기능이었지만, 제가 DEV에서 글을 쓰는 시간이 적지 않다 보니, 제 활동을 한눈에 볼 수 있는 대시보드가 있으면 유용하겠다는 생각이 들었습니다.

확장 프로그램 설정에 DEV API 키를 추가하면 개인 대시보드를 포함한 몇 가지 추가 기능을 잠금 해제할 수 있습니다.

![예시 통계, 차트, 게시물 활동을 보여주는 DEV Tab 대시보드](https://raw.githubusercontent.com/pinkpixel-dev/DEV-tab/main/screenshots/dashboard.png)

대시보드에는 팔로워 수, 조회수, 반응, 댓글, 신규 팔로워 정보가 포함되며, 지난 7일, 30일, 90일 단위로 확인할 수 있습니다.

일별 조회수 차트와 이전 연도를 탐색할 수 있는 활동 히트맵, 그리고 발행된 게시물과 임시 저장된 글 목록도 제공됩니다.

최근 팔로워, 주요 서포터, 그리고 독자들이 어디에서 유입되는지도 확인할 수 있죠. 제가 블로깅을 꾸준히 하면서 가장 갈증을 느꼈던 부분이 바로 이런 통합적인 통계였는데, 직접 만들어보니 어떤 콘텐츠가 반응이 좋았는지, 언제 활동이 활발했는지 한눈에 파악하기 훨씬 쉬워졌습니다.

*참고로 위 대시보드 스크린샷은 가상의 예시 데이터를 사용했습니다.*

## DEV 계정 연결은 전적으로 선택 사항입니다

이 확장 프로그램을 사용하기 위해 계정이나 API 키가 꼭 필요한 것은 아닙니다. 공개 피드, 검색, 필터 및 기타 탐색 기능은 계정 연결 없이도 완벽하게 작동합니다.

하지만 DEV 계정을 연결하면 팔로우하는 태그 기반의 개인 피드, 읽기 목록, 그리고 의미론적 검색(semantic search) 기능까지 이용할 수 있습니다.

API 키는 [DEV 설정](https://dev.to/settings/extensions)에서 생성할 수 있습니다.

이 확장 프로그램은 백엔드, 분석 기능, 또는 추적 기능을 전혀 포함하고 있지 않습니다. 여러분의 API 키는 브라우저의 로컬 확장 프로그램 저장 공간에만 머무르며, 인증된 API 요청을 위해 DEV로만 전송됩니다. 백엔드를 구축하면 개발 비용과 유지보수 부담이 커지기 때문에, 최대한 심플하게 사용자 브라우저 내에서 모든 것을 처리하도록 설계하는 것이 저의 개발 원칙 중 하나입니다.

## 몇 가지 제한 사항

DEV API 때문에 포함하고 싶었지만 그러지 못했던 몇 가지 아쉬운 점이 있습니다.

예를 들어, 확장 프로그램에서 게시물에 직접 반응을 남기거나, 댓글을 달거나, 글을 읽기 목록에 저장할 수는 없습니다.

반응 수와 댓글 미리보기는 가능하지만, 게시물과 상호작용하려면 해당 게시물이 DEV 본 사이트에서 열리게 됩니다.

언젠가는 피드 내에서 이 모든 작업이 직접 가능해지면 좋겠지만, 현재로서는 API가 제공하는 기능의 한계입니다.

## WXT, React, TypeScript로 구축하다

확장 프로그램 프레임워크로는 [WXT](https://wxt.dev/)를 사용했으며, React와 TypeScript를 함께 활용했습니다.

WXT는 이번에 처음 써봤는데, 하나의 코드베이스로 크롬과 파이어폭스를 동시에 빌드할 수 있다는 점이 정말 매력적이었습니다. 매번 두 브라우저의 특성에 맞춰 빌드 스크립트를 따로 관리하던 경험을 생각하면, 이건 개발 생산성을 엄청나게 끌어올려 주는 요소죠.

특히 신경 썼던 부분 중 하나는 새 탭을 열 때마다 피드가 계속해서 모든 것을 다시 가져오지 않도록 하는 것이었습니다. 각 피드의 첫 페이지는 10분 동안 캐시되며, 이전에 로드된 게시물은 오프라인 상태에서도 여전히 표시될 수 있습니다.

작은 부분일지 몰라도, 새 탭 페이지처럼 빈번하게 사용되는 부분을 대체할 때는 이런 사용자 경험이 중요하다고 생각합니다.
